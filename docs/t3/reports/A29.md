## 3. Technische Umsetzung

### 3.1 Körper als Radialprofil

Der Körper ist kein Pfad-Umriss aus festen Koordinaten, sondern ein **Radialprofil** \(r(\theta)\), an
**64 gleichmäßig verteilten Winkeln** abgetastet. Vorteil: jede Form ist ein Vektor aus 64 Zahlen, und
Formwechsel sind lineare Interpolationen der Radien – ohne Morphing-Bibliothek, ohne SVG-Morph-Timing.

Aus dem Referenzvideo wurden drei Profile **gemessen** statt konstruiert (`egg`, `hexagon`, `triangle`);
die restlichen Formen entstehen analytisch aus den Profil-Bausteinen:

| Form | Quelle |
|---|---|
| `circle` | `superellipseProfile` (Exponent 2, Kreis) |
| `pebble` | `superellipseProfile` mit leicht verschobenen Achsen |
| `squircle` | `superellipseProfile` (Exponent ≈ 4) |
| `capsule` | `capsulePath` (zwei Halbkreise + Seiten) |
| `triangle` | gemessenes 64-Punkte-Profil aus dem Referenzvideo |
| `hexagon` | gemessenes 64-Punkte-Profil aus dem Referenzvideo |
| `cloud` | `unionOfCirclesProfile` (Hülle mehrerer Kreise) |
| `drop` | `hullOfCircles` (Spitze + Tropfenkörper) |
| `diamond` | `regularPolygonProfile` (4 Ecken) |
| `star` | `regularPolygonProfile` (5 Zacken, spitze Ecken) |
| `flower` | `unionOfCirclesProfile` (5 Blütenblätter + Kern) |
| `flower`/`pumpkin` | `roundedPolygonProfile` (Kürbis: gerippte Silhouette) |
| `gear` | `profileFromPolygon` (10 Zähne, flache Spitzen, tiefer Einschnitt) |
| `egg` | `superellipseProfile`, unten breiter |

### 3.2 Augen als echte Masken-Löcher

Die Augen sind **keine hellen Formen, die auf dem Körper liegen**, sondern echte Löcher:

- Der Körper wird als `#fff`-Pfad in eine SVG-`<mask>` gezeichnet.
- Die Augen werden als `#000`-Pfade **in dieselbe Maske** geschnitten.
- Darunter liegt eine Farbfläche in der Augenfarbe; durch die Löcher wird sie sichtbar.

Damit ist die Silhouette automatisch die Grenze: wandert ein Auge zum Rand, wird es von der Silhouette
beschnitten – ohne jeden Sonderfall, ohne Clip-Paths, ohne zweite Silhouettenpflege.

Die Augen liegen auf einer **3D-Einheitskugel** (nur \(z > 0{,}02\) wird projiziert) und werden in
Bildschirmkoordinaten transformiert. Ihre Größe skaliert mit dem lokalen Radius am jeweiligen Winkel,
damit sie auch in spitzen Formen (Stern, Raute) nicht aus dem Körper herausschauen.

### 3.3 Deterministische Animation

`liveliness(t)` nutzt periodisches Rauschen (`loopNoise`) und einen deterministischen PRNG
(`mulberry32`) für Blick-Drift, Atmen und Blinzeln. Weil alles eine **reine Funktion der Zeit** ist:

- kein interner Zustand, der auseinanderlaufen könnte,
- Snapshot-Tests sind reproduzierbar,
- `frozen` setzt die Zeit auf `0` und schaltet Drift/Lid-Zustand ab.

### 3.4 Performance – `frozen`

Der kritische Fall ist eine Liste mit 40 Avataren. Zwei Caching-Ebenen sorgen dafür, dass eingefrorene
Avatare **gar keine** CPU verbrauchen:

1. **`FROZEN_CACHE`** in `markup.ts` – der fertige SVG-Markup-String für eine `(shape, color, state,
   expression)`-Kombination wird wiederverwendet.
2. **Pfad-Memoization** in `MascotEngine` – der Body-Pfad wird nur neu berechnet, wenn sich ein Radius
   um mehr als `PATH_EPSILON` geändert hat.

Ohne `frozen` läuft die Zeit über `requestAnimationFrame`. `frozen` hält das Bild **zeitunabhängig**
fest und startet keinen Animations-Loop.

## 9. Risiken und Hinweise

### 9.1 Rechtlich (offene Entscheidung für Stefan)

- Der **Code** ist MIT-lizenziert (Jérémy Perret / bloub) und darf weiterverwendet werden. Die MIT-Lizenz
  und der Copyright-Vermerk stehen in `docs/third-party/bloub-MIT.txt` und im Kopf jeder übernommenen Datei.
- Das **Aussehen** der Figur (Blob mit zwei Augen) imitiert das Design von **x.ai**. Dieses Design ist
  **nicht** lizenziert und wird hier nicht unter MIT verbreitet.
- **Entscheidung für Stefan offen:** Wird das Maskottchen in Connect ausgeliefert? Falls ja, empfiehlt sich
  eine visuelle Eigenständigkeit (z. B. eigene Silhouetten, andere Augenform) oder eine separate
  Gestaltungsscheidung, damit Connect nicht als x.ai-Klon erscheint.
- Empfehlung: In `docs/third-party-notices.md` einen eigenen Abschnitt für bloub anlegen (A01/A40) – die
  Datei listet heute MiroFish, OASIS, REA u. a. auf, aber noch kein bloub.

### 9.2 Technisch

- **2 zusätzliche Formen außerhalb des Vertrags** (`gear`, `egg`) – siehe § 8.
- **Shape-Morphing** zwischen stark unterschiedlichen Formen (Stern → Kürbis) ist eine lineare
  Radius-Interpolation. Bei sehr spitzen Formen kann die Zwischenform unruhig wirken; das ist eine
  Animations-Ästhetik-Frage, keine Fehlerfrage.
- **Augenfarbe** wird als eigene Farbebene unter dem Körper gezeichnet. Bei sehr hellen Körperfarben
  (weiß, creme) ist der Kontrast der Augen abhängig von der Wahl der Augenfarbe pro Farbe – die
  Tabelle in `skins.ts` legt das fest.
- **SSR/Hydration**: `getT3Flag` liefert serverseitig den Default (`false`). Der Client kann das Flag per
  `window`-Runtime-Override aktivieren. Beim ersten Rendern kann der Server-Default also abweichen – das
  ist das bestehende Verhalten des Flag-Mechanismus von A01, kein A29-Sonderfall.
