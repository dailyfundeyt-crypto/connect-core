## 1. Übersicht & Zielerreichung

Ziel der Lane A21 war die Bereitstellung eines universellen, typsicheren und tokenfreien Frontend-Clients mit React-Hooks für alle Frontend-Pakete der Welle W3 (A22–A36) im Connect-Frontend:
- **Ein Client für alle Frontend-Pakete**: Sämtliche HTTP-Fetch-Funktionen und Schnittstellen für Provider, Threads, Chat-Verlauf, Turn-Steuerung, Approvals, Usage & Limits, Cua-Maschinen, Avatare und Flottenstatus.
- **Wort-für-Wort SSE Stream**: Vollwertiger SSE-Stream-Handler (`subscribeT3Stream`), der Text-Deltas, Tools, Kontextwechsel (I5), Approvals, Kosten und Resync-Signale unterbrechungsfrei verarbeitet und automatische Reconnects mit `Last-Event-ID` beherrscht.
- **Komplette React-Hook-Suite**:
  - `useT3Providers`: Treiberliste, Modelle, Verfügbarkeiten (`available`, `unavailable`, `legacy`), Limits.
  - `useT3Chat(agentId)`: Lückenloser Verlauf über alle Generationen hinweg, SSE-Streaming, optimistische Nachrichten-Anzeige, Turn-Abbruch (`interrupt`), Steuerung (`steer`), Freigaben (`respondApproval`).
  - `useT3Control`: Dedizierte Turn-Steuerung, Capabilities-Abfrage und Beantwortung offener Freigaben.
  - `useUsage(query)`: Aggregierte Kosten, Tokens und Provider-Limits (A17/A24).
  - `useMachines`: Cua-Maschinen-Verwaltung (Shared & Per-Agent), `wake` und `sleep` (A19/A26).
  - `useCompanyPublicUsage`: Öffentliche Firmen-Token-Summen und Provider-Splits (A20/A35).
  - `useSchedulerStatus`: Flotten- und Scheduler-Zustand (`idle`, `running`, `waiting_approval`, etc.) mit Concurrency-Limits (A20/A28).
  - `useAgentAvatar`: Mascottchen-Avatar Form (12 Formen), Farbe (13 Farben) und Ausdruck (A20/A29).
- **Robuster Mock-Adapter für W3-Agenten**: Sämtliche Funktionen und Hooks können über `setT3MockMode(true)` oder URL-Parameter `?t3mock=1` (oder Hook-Option `mock: true`) vollständig ohne laufenden lokalen T3-Server oder Backend genutzt werden. Simuliert zeitverzögerte SSE-Streams und Zustandsspeicherung im Speicher.
- **Keine Tokens im Browser**: Authentifizierung erfolgt strikt über Better-Auth Session-Cookies (`credentials: "include"`). Es werden unter keinen Umständen API-Keys, Bridge-Tokens oder Passwörter im `localStorage`, `sessionStorage` oder Browser-State abgelegt.
- **Feature-Flags**: Orientiert an `contracts.ts` (A01). Bei inaktivem Flag verhalten sich Client und Hooks defensiv bzw. signalisieren Deaktivierung.

## 6. Hinweise & Leitfaden für W3-Agenten (A22–A36)

Alle W3-Agenten können ab sofort direkt auf `@/lib/t3` zugreifen:

### Beispiel 1: Chat-Bausteine (A22)
```tsx
import { useT3Chat } from "@/lib/t3";

export function T3ChatComponent({ agentId }: { agentId: string }) {
  const { messages, status, isStreaming, pendingApprovals, sendMessage, interrupt, respondApproval } = useT3Chat(agentId);
  // Rendert Nachrichten, Stream, Tool-Calls und Freigabekarten
}
```

### Beispiel 2: CLI-Auswahl (A23)
```tsx
import { useT3Providers } from "@/lib/t3";

export function T3CliSelector() {
  const { providers, activeProviders, isProviderAvailable } = useT3Providers();
  // Zeigt Codex, Claude, Grok etc. im selben Look wie bisheriges Dropdown
}
```

### Beispiel 3: Nutzungsansicht (A24)
```tsx
import { useUsage } from "@/lib/t3";

export function T3UsageView() {
  const { data, totals, buckets, loading } = useUsage({ metric: "cost", windowDays: 30, groupBy: "agent" });
  // Zeigt Kosten, Tokens, Cache-Ersparnisse und Limits
}
```

### Beispiel 4: Mock-Modus für Offline-Entwicklung
```tsx
import { setT3MockMode } from "@/lib/t3";

// Aktiviert vollen Mock-Modus für alle Hooks ohne Server
setT3MockMode(true);
```

## 7. Risiken & Gegenmaßnahmen

1. **Netzwerkunterbrechung während langem SSE-Streaming**:
   - *Gegenmaßnahme*: `subscribeT3Stream` führt `currentLastEventId` kontinuierlich mit und sendet beim automatischen Wiederverbindungsversuch den Header `Last-Event-ID`. Liegt eine Lücke vor, signalisiert der Server `event: resync`, woraufhin `useT3Chat` automatisch `refetchHistory()` aufruft.
2. **Mehrfaches Senden identischer Anfragen**:
   - *Gegenmaßnahme*: `sendMessage` generiert immer eine client-seitige ID (`clientMessageId`), die server-seitig (A11 Idempotency) dedupliziert wird.
3. **Leckage von Zugangsdaten / Tokens**:
   - *Gegenmaßnahme*: Keine Speicherung im Browser. Alle Abfragen nutzen `credentials: "include"` und Better-Auth HttpOnly-Cookies.
