### Abdeckung der Testsuite:

1. **Text-Coalescing (`message.updated`):**
   - Streaming-Deltas werden berechnet und als `text_delta` emittiert.
   - Mehrfache Deltas werden gepuffert und akkumuliert.
   - Stream-Abschluss (`streaming: false`) flusht den Puffer und emittiert `text_done`.
   - User-/System-Nachrichten erzeugen kein Echo im Chat.

2. **Tool-Events (`turn-item.updated`):**
   - `command_execution` → `tool` (Label `Bash`, Titel, gekürzte Ausgabe, Zeitstempel).
   - `file_change` → `tool` (Label `Edit`, Pfad, Additions/Deletions `+N -M`).
   - `file_search` → `tool` (Label `Suche`, Suchmuster).
   - `web_search` → `tool` (Label `Web`, Suchbegriffe).
   - `dynamic_tool` → `tool` (dynamisches Tool-Label und Parameter).
   - `reasoning` → `tool` (Label `Denke nach`).
   - `compaction` → `tool` (Label `Kontext kompaktiert`).
   - `handoff` → `tool` (Label `Kontext übergeben`).
   - `checkpoint` → `tool` (Label `Checkpoint`, Dateianzahl).
   - `run_interrupt_request` / `run_interrupt_result` → `tool` (Unterbrechungsmeldung).
   - `system_notice` → `tool` (Systemmeldung).
   - `error` → `error` (Fehlermeldung, Fehlerklasse, Retry-Flag).

3. **Freigaben und Rückfragen:**
   - `approval_request` (TurnItem) → `approval` (Request-Kind, Prompt, Optionen, `blocking: true`).
   - `user_input_request` (TurnItem) → `approval` (Rückfrage an den Nutzer).
   - `secret_request` (TurnItem) → `approval` (Geheimnis-Eingabeaufforderung).
   - `runtime-request.updated` → `approval` (Zustandsaktualisierungen).

4. **Planung und Sub-Agenten:**
   - `plan.updated` (`todo_list`) → `plan` (Schritte mit Status `queued`, `running`, `done`).
   - `plan.updated` (`proposed_plan`) → `plan` (Markdown-Plan).
   - `subagent.updated` → `subagent` (Name, Treiber, Status).
   - `turn-item.updated` (`subagent`) → `subagent` + ggf. Tool-Zeile für Fortschritt.

5. **Token-Nutzung und Kontext-Trenner:**
   - `provider-turn.updated` → `usage` (Uncached Input, Cached Input, Output, Reasoning).
   - `context-handoff.updated` → `context_switch` (Zusammenfassung, Thread-IDs, Zeitstempel).
   - `context-transfer.created` → `context_switch` (Tokenstand bei Wechsel, Quell-/Ziel-Thread).

6. **Terminaler Turn-Abschluss:**
   - `run.updated` mit Status `completed` / `failed` / `cancelled` / `interrupted` → `turn_end` (Status, Dauer in ms).
   - Nicht-terminale Status (`running`, `queued`) erzeugen kein `turn_end`.
   - Vor `turn_end` wird ein eventuell noch offener Textpuffer automatisch geflusht (`text_done`).

7. **Kürzung von Befehlsausgaben (`truncateCommandOutput`):**
   - Ausgaben unterhalb der Schwelle (Standard: 25 Zeilen) bleiben vollständig erhalten.
   - Lange Ausgaben behalten Kopf (10 Zeilen) und Ende (10 Zeilen); der Mittelteil wird durch `… N Zeilen ausgeblendet …` ersetzt.

8. **Crash-Sicherheit & Vorwärtskompatibilität:**
   - 100 % unbekannte Event-Typen, `null`, `undefined` oder ungültige Payloads werden ignoriert und im Zähler `unknownEventCount` erfasst, ohne Exception.
   - Reine Metadaten-Events (`thread.created`, `node.updated`, `checkpoint.captured`, etc.) werden ohne Chat-Ausgabe verarbeitet.

3. **Hinweis an A02 (Sidecar-Supervisor):**
   - Im Test `apps/server/src/t3-bridge/sidecar/sidecar.test.ts:176` prüft der Test, ob `supervisor.start({ force: false })` den Zustand `stopped` meldet. Wenn jedoch auf dem Rechner bereits ein T3-Sidecar auf Port 3773 aktiv läuft, erkennt `probeExistingRuntime` diesen und meldet `running`.
