Agent: **A07** · Datum: 29.10.2026 · Welle W1 · Abhängigkeiten: A01 (Verträge), A05 (`agent_workspace`) · Ergebnis: **erfüllt**

## 1. Ergebnis in drei Sätzen

Jeder Agent bekommt genau einen Arbeitsordner unter `%LOCALAPPDATA%\ConnectAgents\workspaces\<agentSlug>\`; ein zweiter Agent mit gleichem Namen erhält `-2`, `-3` usw. und nie denselben Ordner. Vorhandene Projektordner können ausdrücklich zugewiesen werden, nachdem der Pfad gegen `..`, Systemordner, Connect-Repo, T3-Fork, Helium-Profil und Connects eigene Daten geprüft wurde. Ordner werden **nie gelöscht** — „Agent löschen“ archiviert nur den Eintrag; Speicherplatz pro Ordner wird begrenzt gemessen und steht A09 zur Verfügung. Alles hängt am Flag `connect.t3.bridge`: aus = kein Ordner, keine Datei, kein Datenbankzugriff.

## 3. Verhalten

### 3.1 Standardordner

```
%LOCALAPPDATA%\ConnectAgents\workspaces\<agentSlug>\
```

* Wurzel: `getAgentWorkspaceRootDir()`; Fallback ohne `LOCALAPPDATA`: `~/.connect-agents/workspaces`.
* Slug: nur `a-z`, `0-9`, `-`; Umlaute werden transliteriert (`Max Müller` → `max-mueller`,
  `Grüße & Co.` → `gruesse-co`), reservierte Windows-Namen (`con`, `nul`, `com1` …) werden
  entschärft (`agent-con`), Obergrenze 48 Zeichen. Punkte und Pfadtrenner sind unmöglich —
  ein Agentenname kann nicht aus der Wurzel ausbrechen.
* Im Standardordner liegt `.connect-workspace.json` mit `agentId`, `slug`, `createdAt`
  (nur wenn die Datei noch nicht existiert; wird nie überschrieben). Projektordner bekommen
  **keinen** Marker, damit Stefans Ordner unangetastet bleiben.
* Registry: `<Wurzel>\_registry.json` (JSON, versioniert), Sicherung `_registry.json.bak`.
  Schreiben: Sicherung → temporäre Datei → `rename` (atomar). Nichts wird gelöscht.
* Archivierte Slugs bleiben vergeben: Ein neuer Agent erbt nie den Ordner eines alten.

### 3.2 Projektordner zuweisen (nur nach Stefans Auswahl)

```ts
const result = await manager.assignProjectFolder({
  agentId,
  agentName,
  path: "C:\\Users\\Kunc GmbH\\Projekte\\Kunden Seite", // aus der UI gewählt
});
```

* Der Ordner muss existieren und ein Verzeichnis sein; `createIfMissing: true` legt ihn an.
* Es wird nichts verschoben, geleert oder gelöscht. Ein früherer Ordner desselben Agenten
  bleibt vollständig auf der Platte; nur der Registry-Eintrag zeigt auf den neuen Pfad.

### 3.3 Pfad-Validierung (`validateWorkspacePath`)

Rein rechnerisch (kein Dateisystemzugriff auf den Kandidaten), damit sie **vor** jedem
Anlegen greift und deterministisch testbar ist. Abgelehnt werden:

| Code | Beispiel |
|---|---|
| `empty` | `""`, nur Leerzeichen |
| `not_absolute` | `Projekte\Agent` |
| `traversal` | `…\workspaces\..\Windows` (roh geprüft, bevor `resolve()` es wegnimmt) |
| `unc` | `\\server\share\agent`, `\\?\C:\…` |
| `drive_root` | `C:\` |
| `system_dir` | `C:\Windows\System32`, `C:\Program Files\…`, `ProgramData`, `%APPDATA%` |
| `home_root` | `C:\Users\Kunc GmbH`, `…\Desktop`, `…\Documents`, `…\Downloads`, `.ssh`, `.gemini` |
| `protected_project` | Connect-Repo (auch `OpenBot-v2*`-Geschwister), T3-Fork, `~/.t3`, `~/.t3-hermes` |
| `helium_profile` | `%LOCALAPPDATA%\imput\Helium\…` (Regel 6/11) |
| `connect_data` | `%LOCALAPPDATA%\ConnectApp\…`, `ConnectAgents\…` außerhalb von `workspaces` |
| `workspaces_root` | die gemeinsame Wurzel selbst |
| `in_use` | Ordner eines anderen Agenten (Groß-/Kleinschreibung egal) |
| `nested` | Ordner liegt in einem anderen Agentenordner oder umgekehrt |

Windows-Pfade mit Leerzeichen (`C:\Users\Kunc GmbH\…`) sind ausdrücklich erlaubt und
getestet; `C:`/`c:` und `/`/`\` werden auf Windows als gleich behandelt.

### 3.4 Nie löschen — nur archivieren

```ts
await manager.archive(agentId); // Status = archived, archivedAt gesetzt
```

* Kein `rm`, kein `rename`, kein Leeren. Ordner, Marker und alle Arbeitsdateien bleiben.
* `ensure()` mit derselben Agent-Id findet den archivierten Ordner wieder
  (`reactivated: true`), statt einen neuen anzulegen.
* Ein **anderer** Agent bekommt niemals den archivierten Ordner (Slug bleibt belegt).

### 3.5 Speicherplatz für A09

```ts
const report = await manager.measureAll({ concurrency: 2 });
// { enabled, rootDir, measuredAt, totalBytes, workspaces: [{ agentId, slug, status, bytes, files, … }] }
```

* Standardgrenzen: 50 000 Einträge, Tiefe 20, 10 Fehlermeldungen, `AbortSignal` möglich.
* Symlinks/Junctions werden nicht verfolgt (keine Schleifen, kein Ausbruch).
* Zugriffsfehler brechen nicht ab, sie landen in `errors`; `truncated` zeigt Grenzen an.
* Einzelabfrage: `manager.measure(agentId)`.

### 3.6 Datenbank-Spiegelung (A05)

* `createDrizzleWorkspaceStore(db)` schreibt/liest `agent_workspace` (`agent_id`, `path`).
* Optional: `createAgentWorkspaceManager({ dbStore })`. Fehlt die Tabelle (Migration 0570
  noch nicht eingespielt), wird **einmal** geloggt und weitergearbeitet — die Registry-Datei
  ist die Wahrheit.
* Die Tabelle kennt weder `slug`, `kind` noch `archived_at`; deshalb liegt der Status
  ausschließlich in der Registry (Wunsch an A05 siehe §8).

### 3.7 Feature-Flag

* `isT3WorkspaceManagerEnabled()` = `getT3Flag("bridge")` (A01-Vertrag).
* `getAgentWorkspaceManager()` liefert `null`, wenn das Flag aus ist; jede Methode prüft
  zusätzlich **bei jedem Aufruf**. Flag aus = kein `mkdir`, keine Registry, kein DB-Zugriff
  (Test: Wurzelverzeichnis existiert danach nicht).
* Kein stiller Fallback: A11/A18 dürfen bei `disabled` nicht heimlich den alten Ordner
  benutzen, sondern müssen den Fehler melden (analog zur Laufzeit-Regel aus A01).

### 3.8 Schnittstelle für die Verdrahtung

```ts
import {
  getAgentWorkspaceManager,
  createAgentWorkspaceManager,
  createDrizzleWorkspaceStore,
} from "./t3-bridge/workspaces";

const manager = getAgentWorkspaceManager();          // null bei Flag aus
if (!manager) return legacyBehaviour();

const ensured = await manager.ensure({ agentId, agentName });
if (!ensured.ok) return error(ensured.reason);
const cwd = ensured.workspace.path;

// oder mit Datenbank-Spiegelung:
const withDb = createAgentWorkspaceManager({
  dbStore: createDrizzleWorkspaceStore(db),
});
```

Wichtige Methoden: `ensure`, `assignProjectFolder`, `archive`, `unarchive`, `list`, `get`,
`takenPaths`, `measure`, `measureAll`.

## 7. Bewusste Entscheidungen

1. **Registry-Datei ist die Wahrheit, Datenbank nur Spiegel.** Grund: `agent_workspace`
   (A05) hat nur `path`; Slug/Art/Status fehlen, und die Migration ist noch nicht im
   Journal (A40). So funktioniert der Manager auch vor der Migration.
2. **Erst registrieren, dann `mkdir`.** Bricht das Anlegen ab, bleibt der Pfad reserviert
   und kann keinem zweiten Agenten zufallen.
3. **`archive` fasst das Dateisystem nicht an.** Nur der Registry-Eintrag ändert sich.
4. **Kein automatisches Einsammeln von Projektordnern.** Zuordnung nur über den expliziten
   Aufruf (Stefans Auswahl), nie durch Scannen von `Downloads` o. ä.
5. **Validierung rein rechnerisch.** Die Existenzprüfung passiert erst im Manager, damit
   Tests ohne Dateisystem laufen und die Prüfung nicht von Zufälligkeiten abhängt.
6. **Geschützte Wurzeln werden zur Laufzeit ermittelt** (Repo-Erkennung über
   `package.json` + `apps/server/package.json`, Geschwister `OpenBot-v2*`, T3-Pfad aus A02).
   Keine fest verdrahteten Nutzerpfade außer dem bereits von A02 genutzten T3-Standard.

## 9. Risiken

| Risiko | Einschätzung | Gegenmaßnahme |
|---|---|---|
| Registry-Datei beschädigt | Mittel (Handedit, Absturz beim Schreiben) | Atomares Schreiben + `_registry.json.bak`; defekte JSON fällt auf Sicherung zurück (getestet) |
| Zwei Serverprozesse schreiben gleichzeitig | Niedrig (Architektur: ein Connect-Server) | Schreibvorgänge im Prozess serialisiert; Datei ist klein. Bei Mehrprozess-Betrieb bräuchte es ein Lock — offener Punkt |
| Migration 0570 fehlt in der Live-DB | Wahrscheinlich bis A40 | DB-Spiegelung ist best effort und blockiert nie; Registry bleibt Wahrheit |
| Projektordner wird extern gelöscht | Niedrig | `ensure()` legt ihn wieder an (Ordner bleibt dem Agenten zugeordnet) — bewusst, aber überraschend; im Bericht dokumentiert |
| Messung großer Ordner | Mittel bei 40 Agenten | Grenzen (50 000 Einträge, Tiefe 20), `truncated`, Nebenläufigkeit 2, Abbruch via `AbortSignal` |
| Pfad-Heuristik erkennt ein neues Repo nicht | Niedrig | Erkennung über `package.json` + `apps/server/package.json`; zusätzlich werden `OpenBot-v2*`-Geschwister geschützt. Ein neu geklontes Fremdprojekt kann nur durch explizite Zuweisung hereinkommen |
| Windows-Pfadlänge > 260 Zeichen | Niedrig | Slugs max. 48 Zeichen; Projektpfade kommen von Stefan. Kein Test für Long-Paths |
| Symlinks/Junctions | Niedrig | Werden bei der Messung übersprungen; Validierung verbietet UNC, nicht aber lokale Junctions (bewusst, um bestehende Projektordner nicht abzulehnen) |
