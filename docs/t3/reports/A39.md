### 4.5 Rechtes Panel: Bot-Panel (Aufgabe 4)

**`detail-panel.tsx`** — das Panel rendert jetzt `BotPane` (A27: Details / Bibliothek / Computer).

Zwei Entscheidungen, die hier wichtig waren:

**a) Kein Router-Hook.** Der Agent kommt nicht aus `useParams()`/`useRouterState()`. Das Panel
wird auch ohne `RouterProvider` gerendert (Tests, eingebettete Flächen) — ein Router-Hook hätte
dort geworfen und den bestehenden Test `apps/app/tests/detail-panel.test.tsx` gebrochen. Statt
dessen liest eine kleine Helferin die Route aus dem Pfad:

```ts
function readAgentIdFromLocation(): string | undefined {
  if (typeof window === "undefined") return undefined;
  const match = window.location.pathname.match(/\/agent\/([^/]+)/);
  return match ? decodeURIComponent(match[1]) : undefined;
}
```

**b) Kein Router-Hook, aber auch keine eigene Query.** `BotPane` holt sich die Agent-Daten in
seinem Details-Tab selbst. Eine zweite Query an derselben Stelle wäre doppelt — und hätte
`DetailPanel` an einen `QueryClient` gebunden, den es bislang nicht brauchte (das Panel wird
z. B. auch im `skills`-Bereich ohne QueryClient gerendert).

**Reihenfolge der Wahrheit:** Was der Aufrufer als `detail` übergibt, gewinnt immer. Das ist
wichtig, weil die Agent-Route beim „Zusehen“ (`watch=true`) das **laufende Bild** als `detail`
übergibt — das Bot-Panel darf eine bestehende Live-Ansicht nicht verdrängen. Erst wenn nichts
übergeben wird, füllt das Bot-Panel die Lücke:

```tsx
const panelContent =
  detail ??
  (botPaneEnabled ? <BotPane agentId={routeAgentId as string} name="Bot" /> : null);
```

### 4.7 Firmenprofil: Token-Verbrauch (Aufgabe 6)

**`company-profile-x.tsx`** — direkt unter dem `CompanyMarketplaceStrip`:

```tsx
<CompanyTokenUsageSection companyId={company.id} isAdmin />
```

Die Sektion aus A35 liefert Widget **und** Admin-Schalter und prüft das Flag
`companyPublicUsage` selbst — ist es aus, rendert sie nichts.

`isAdmin` wird **bewusst immer gesetzt**: der Server entscheidet. A20 antwortet Nicht-Admins

Admin-Regel im Client wäre eine zweite Wahrheit — und die Skill-Regel „Render das, was der
Server entschieden hat, statt es selbst zu berechnen“ sagt genau das.

### 4.8 Onboarding: Maschinen-Schritt (Aufgabe 7)

**`onboarding.tsx`** — der Maschinen-Schritt (A26) kommt **vor** „Fertig“ in den Ablauf, aber
nur mit Flag `cuaMachines`.

Zwei Dinge, die dabei leicht falsch gehen und hier bewusst gelöst sind:

**a) Adressierung über Id, nicht über Nummer.** Die Schritte werden über ihre **Id** gerendert
(`currentStepId === "welcome"` usw.) statt über `stepIndex === 0`. Sonst hätte das Einschieben
des Maschinen-Schritts jeden folgenden Schritt um eine Position verschoben.

**b) Die Schritteliste ist dynamisch.** `onboardingSteps()` hängt den Maschinen-Schritt an,
wenn das Flag gesetzt ist. Alle Längenprüfungen (`steps.length`) und die Server-Synchronisation
(`steps[nextIndex]?.id`) laufen gegen diese Liste — der gespeicherte Schrittindex bleibt
gültig, weil der Maschinen-Schritt **vor** „Fertig“ (dem letzten Schritt) sitzt.

Der Schritt selbst ist **optional**: `MachineOnboardingStep` lässt sich überspringen, damit das
Onboarding nie an einer fehlenden Maschine hängen bleibt.

## 10. Risiken & Gegenmaßnahmen

1. **Ein Flag an zwei Stellen** (Aufrufstelle **und** Komponente). Beispiele: `AgentGrid` prüft
   `mascot` selbst, und `app-sidebar.tsx` prüft es nochmal. Das ist **Absicht**, aber nur
   deshalb unkritisch, weil die **Aufrufstelle** die Entscheidung trifft: das Raster ersetzt die
   alte Liste, statt sich daneben zu stellen. Wäre die Reihenfolge umgekehrt (Flag nur in der
   Komponente), wäre die Sidebar bei ausgeschaltetem Flag leer.
2. **Pfadlektüre statt Router-Hook.** `readAgentIdFromLocation()` liest `/agent/<id>` aus dem
   Pfad. Das ist bewusst simpel gehalten: `/agent/<id>` ist die einzige Route, auf der ein Bot
   seine eigene Leiste hat. Sollte Connect später eine zweite Bot-Route bekommen, ist das die
   Stelle, die angepasst werden muss.
3. **`isAdmin` wird immer gesetzt.** Der Client behauptet damit nichts Falsches: er sagt „ich
   frage mal nach“, und der Server antwortet `403` für Nicht-Admins. Die Sektion blendet die
   Schalter dann aus. Es gibt keine zweite Admin-Wahrheit im Client.
4. **Der Onboarding-Schrittindex.** Der Maschinen-Schritt sitzt vor dem letzten Schritt, damit
   ein gespeicherter Index (`sessionStorage`) gültig bleibt. Wäre er hinten eingefügt, hätte ein
   angefangenes Onboarding nach dem Neuladen den falschen Schritt gezeigt.
